# Момент

Сервис персональных цифровых подарков на Django. Гость собирает подарок и смотрит превью без регистрации. После входа и подтверждённой оплаты сервер выдаёт защищённую ссылку. Название ссылки выбирает отправитель; к нему добавляется случайный секрет. Получатель открывает подарок явным нажатием, поэтому загрузка страницы ботом не считается открытием.

## Возможности

- **Лайт — 200 ₽:** базовый шаблон, текст, до 3 фото, ссылка на 7 дней, подпись сервиса.
- **Стандарт — 350 ₽:** все обычные шаблоны, до 10 фото, музыка, ответы, ссылка на 30 дней.
- **Премиум — 450 ₽:** видео MP4 до 50 МБ, два анимированных шаблона, отложенная выдача ссылки отправителю и уведомление о первом открытии. Отправитель сам решает, когда переслать готовую ссылку. Повторный просмотр разрешён, пока ссылка действует.

Цены и лимиты хранятся в таблице `gifts_tariff`; стартовые значения создают миграции. Их можно менять в базе без нового релиза. Уже созданный платёж сохраняет свою сумму.

## Локальный запуск

```bash
cd gift-site
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export DJANGO_DEBUG=1
python manage.py migrate
python manage.py runserver 127.0.0.1:8000
```

Открой `http://127.0.0.1:8000/`. В режиме разработки коды входа по email печатаются в терминал. Для сохранения сессий между перезапусками задай постоянный `DJANGO_SECRET_KEY` в своей среде; файл с ключом в проект не добавляй.

Без ключей платёжного магазина конструктор, превью и черновики работают, а оплата отвечает сообщением о ненастроенном сервисе. Реальные платежи здесь не выполнялись.

## Настройка внешних сервисов

Задавай значения через переменные окружения на сервере. Не помещай секреты в HTML, репозиторий или архив проекта.

| Назначение | Переменные |
| --- | --- |
| Django и база | `DJANGO_SECRET_KEY`, `DJANGO_ALLOWED_HOSTS`, `DJANGO_CSRF_TRUSTED_ORIGINS`, `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_HOST`, `POSTGRES_PORT` |
| Почта | `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`, `EMAIL_USE_TLS`, `EMAIL_TIMEOUT`, `DEFAULT_FROM_EMAIL` |
| ЮKassa | `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, `YOOKASSA_SEND_RECEIPT`, `YOOKASSA_VAT_CODE` |
| Telegram | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` |
| VK ID | `VK_ID_APP_ID` |

Для рабочего сервера оставь `DJANGO_DEBUG` выключенным, настрой PostgreSQL, HTTPS и почту. Домен сайта добавь в настройки Telegram-бота. В кабинете приложения VK ID укажи точный callback `https://ТВОЙ-ДОМЕН/api/auth/vk/callback/` и тот же домен, с которого начинается вход. Токены VK ID после проверки аккаунта не сохраняются.

Для ЮKassa настрой уведомления на `https://ТВОЙ-ДОМЕН/api/payments/yookassa/webhook/` о `payment.succeeded`, `payment.canceled` и `refund.succeeded`. Сервер повторно запрашивает статус, ID, сумму и валюту у ЮKassa; клиентский возврат со страницы оплаты не публикует подарок. Для чеков включи `YOOKASSA_SEND_RECEIPT=1`, настрой `YOOKASSA_VAT_CODE` под свой налоговый режим и предоставь контактный email покупателя. Условия 54-ФЗ и параметры магазина проверь перед приёмом реальных денег.

## Как устроена отложенная ссылка

Для Премиума можно выбрать дату и время **выдачи ссылки отправителю**. Ссылка появится в «Моих подарках» после этого времени. Кабинет обновляется раз в минуту, пока вкладка открыта, и при возвращении на неё. Получателю сервис ничего не отправляет автоматически.

## Что проверено

Локально прошли миграции и `manage.py check`, проверка синтаксиса JavaScript, сценарии email и VK ID, права владельца, черновики, тарифы, расписание, явное открытие, ответ, уведомление и возврат. Обмен с ЮKassa, VK ID и Telegram проверялся имитацией ответов; для проверки с реальными провайдерами нужны их настройки и публичный HTTPS-домен. В этой среде локальный HTTP-сервер не удалось запустить из-за запрета на открытие порта, поэтому после последних правок браузерную проверку выполняй на своей машине.
